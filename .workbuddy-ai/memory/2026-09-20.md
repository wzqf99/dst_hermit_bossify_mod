## 帝王蟹胜利演出 —— 位置改为固定点（第 3 版）

用户实测反馈：演出效果 OK，但**生成位置太贴近岛**，要求固定在
奶奶岛太极图案的「非陆地」海面，即后期铺设天体后羿战场的位置。

### 关键突破：找到权威锚点 —— 天体战场中心

原版 `components/wagpunk_arena_manager.lua`：

```lua
local ARENA_CENTER_X = -3.5 * TILE_SCALE   -- = -14
local ARENA_CENTER_Z = -5.5 * TILE_SCALE   -- = -22
```

`WALLSPOTS` 修正时写着 `v[1], v[2] = v[1] - 14, v[2] - 22`
（注释 *Move from center to arena origin*）——这证明这两个偏移就是
相对 **hermitcrab_marker** 的。

→ **战场中心 = hermitcrab_marker 位置 + (-14, -22)**

战场墙环 `WAGPUNK_ARENA_COLLISION_DATA`（`componentutil.lua` 852 行）
是 32 个点、半径 28 的八边形环，正中就是这个点。

### 岛屿与战场的几何关系（已核算）

从 `hermitcrab_01.lua` 的 BG_TILES 层解出 20×20 陆地掩码：

- 陆地 320 格，世界坐标 x ∈ [-38, 34]，z ∈ [-38, 38]
- 海面缺口（太极的「非陆地」）在**左侧（西）偏下**，质心约 (-35, 4)
- 战场覆盖 x ∈ [-42, 14]，z ∈ [-50, 6]
- 战场中心 (-14, -22) 距岛心 26.1 单位（6.5 格），方位角约 -122.5°（西南）

**注意**：早期我按「岛心朝南搜索」找点，方向就错了——战场不在正南，
而在西南。这就是「太贴近岛」的原因。

### 位置微调（第 4 版）：-14/-22 → -20/-12

用户实机反馈：墙环中心 (-14,-22) 落在湖面**右下角**、仍偏贴陆地，
希望再往左上挪到湖心。

两套独立方法交叉验证，结果一致：

| 方法 | 得到的目标偏移 |
| --- | --- |
| 实机截图量测（按地形像素宽标定比例尺 4.12 px/单位） | (-20.4, -11.7) |
| 静态布局掩码反推（hermitcrab_01 + 截图对齐） | 约 (-20, -12) |

→ 最终采用 **`marker + (-20, -12)`**。

### 新位置解析优先级

1. **首选固定点**：`marker + (-20, -12)`，湖心偏左上
2. 该点不可用 → 围绕它 6 单位环上试 8 个方向
3. 整片都不可用 → 兜底：从岛心向西南（`-0.75 * PI`）搜第一个海面点

参数全在 `tuning.VICTORY_EPILOGUE`：
`ARENA_OFFSET_X = -20` / `ARENA_OFFSET_Z = -12` / `ARENA_SEARCH_RADIUS = 6`。
（`victory_epilogue.lua` 里 `or` 的兜底默认值必须与 tuning 同步，别只改一处。）

### 踩过的坑（务必牢记）

- **岛屿会旋转**：`hermitcrab_relocation_manager` 按
  `monkeyisland_01` 里 monkeyqueen→portal 的角度旋转整个布局。
  所以不能硬编码世界绝对坐标，必须用 `marker + 偏移` 的相对写法。
- **`Map:GetWagPunkArenaCenterXZ()` 不通用**：它读
  `wagpunk_floor_helper` 的 netvar，而那个 netvar 只在**玩家真正
  开始铺设战场后**才被设置。战斗时若还没铺，返回 nil。
  所以自己算偏移更稳。
- **坐标单位别搞混**：`TILESPOTS` 里的整数是「格」，用时要乘
  `TILE_SCALE`(=4)；`WAGPUNK_ARENA_COLLISION_DATA` 里的是世界单位，
  直接用，且只减 14/22 的偏移、不再乘 4。
