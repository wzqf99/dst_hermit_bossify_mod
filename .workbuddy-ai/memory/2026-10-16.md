### 技术突破（可复用，已存 `vanilla_assets/tools/`）
**DST `build.bin`（spriter build）格式终于完整破解**，之前技能里只解码 tex 不解析 build：
```
'BILD' | u32 version | u32 num_symbols | u32 num_frames_total
| u32 len + build_name | u32 num_atlases | (u32 len + atlas_name)*
| per symbol: u32 hash, u32 num_frames, frames[] (每帧 32 字节)
   帧记录 = u32 frame_idx, u32 ?, f32 pivot_x, f32 pivot_y, f32 w, f32 h, u32 v0, u32 vn
     ← v0 = 顶点起始下标, vn = 顶点数
| u32 num_verts | 顶点数组 (每个 24 字节 = 6 个 f32: x, y, z, u, v, w)
| u32 num_hashes | (u32 hash, u32 len, name)*   ← 名称表在**文件尾部**
```
- 精灵的图集矩形 = 该精灵 `[v0, v0+vn)` 顶点里 u/v 的 min/max × 图集尺寸；
  **v1 是下边缘**，像素 y = `(1 - v) * H`。
- 每个精灵 6 个顶点 = 2 个三角形（TL,TR,BL / TR,BR,BL），复杂部件可多 quad。
- 关键判据：帧数据区末尾的 `num_verts` 恰好等于所有 `vn` 之和（二阶段 3924），可自校验。

**`anim.bin` 只做到一半**：定位到了尾部名称表（25 条，含符号名与 build 名），
元素记录 40 字节 = `u32 hash1, u32 0, u32 hash2, 7×f32`，元素间距 40 字节；
但变换矩阵语义未解出，**没做骨骼渲染**。

## 追加：程序化重上色跑通（`vanilla_assets/recolor_out/`）

用户问「这个方案可行性怎样？你能直接实施?」→ 直接实施了，证明配色改造**不需要重画**。

### 做法与结果
`tools/recolor.py`（约 120 行）：色相分段线性搬迁 + 按明度分段的饱和度/明度曲线，alpha 与像素位置完全不动。

实测（用户概念图 vs 输出）：
| | 主色相带 | 饱和中位 |
|---|---|---|
| 原版图集 | 165–225° 青蓝 85% | 0.22 |
| 输出 | 330–15° 绯红 **94%** | **0.47** |
| 概念图 | 330–15° 绯红 88% | **0.47** |

### 关键教训（下次别踩）
- **`sat_curve` 中间调必须给低增益。** 第一版在 v≈0.4 给 1.2，结果整块岩板染粉。
  原因：原版岩块 45% 像素是「中调蓝灰岩面 v 0.3~0.5, s≈0.30」，它该压成中性暗灰；
  只有约 5% 的亮边（v>0.7）才该变粉。30% 是纯黑描边（v<0.15, s=0）不用管。
- 参数化设计成三条曲线（hue / sat_curve / val_curve），支持 `--override` 传 JSON 覆盖，迭代很快。

### 结论性判断
- 「改配色」这类需求：程序化 20~120 行搞定，81 帧天然一致、可复现、可微调，**比任何生成式模型逐帧重绘都靠谱**。
- 唯一真需要「画」的是概念图上织影者的双角骷髅头 + 肋骨胸腔 —— 原版二阶段 build 无对应符号。
- 用户对 AI 绘图工具的疑问：SVG 不适合（源是软 alpha 位图、产物要 KTEX）；LLM 爱用 SVG 是因为 SVG 是文本，
  不是因为它适合。GPT-6 Astra 有原生 Image Generation 工具，Opus 5.5 定位是写代码/调 API 不产像素。

## 追加：出 v0.1 boss 成品（`alterguardian_crimson/`）

用户要「先出一版boss，骷髅头/胸腔下一版」。做完了，12 项自检全过。

### 技术突破：自写 KTEX 编码器（本机无 Mod Tools）
`tools/tex_encode.py`。关键坑：
- **Pillow 的 DDS 写入器是自上而下存像素，KTEX 是自下而上** → 编码前必须 `FLIP_TOP_BOTTOM`，
  否则贴图在游戏里上下颠倒。不翻转时往返误差 RGB 46.9 / Alpha 96.4，翻转后降到 1.2 / 0。
- DXT 按 4×4 块工作，边角不足 4 的要补到 4 再压；pitch = ceil(w/4)*16。
- **原版位域 `0xfffd6220`**（platform 0 / DXT5 / texture_type 1 / 11 层 mip / flags 3 / fill 4095）。
- 自写编码器输出与原版**文件大小完全相同**（1398246 字节）。

### 关键技巧：alpha 块原样接回
重上色不动 alpha，所以不必重新压 alpha —— 直接把原版 tex 每 16 字节 DXT5 块的**前 8 字节
（alpha）** 覆盖到新块上。结果 alpha 与原版**位级一致**（平均差 0.00），
避免二次量化。`tex_encode.encode(..., alpha_from=<原版tex>)`。

### build.bin 回写
`tools/build_pack.py`：解析 + 序列化。**不改名回写时与原文件逐字节一致**（自校验通过）。
只改 build 名 → 新 build 配原版 bank 就能播全部动画。名称表里只有符号名，没有 build 名。

### mod 结构
`_build.zip` 只含 `atlas-0.tex + build.bin`（本体验证：`hermitcrab_build.zip` 就是这样），
所以资源包只有 336KB，不用重新分发 Klei 的 anim.bin。

### ⚠️ 关键坑：简单 postinit 会被 stategraph 覆盖
原版 `SGalterguardian_phase2.lua` 有三处 SetBuild：
spawn.onenter→spawn_death、**spawn.onexit→"alterguardian_phase2"（会把 reskin 冲掉）**、death.onenter→spawn_death。
必须 `AddStategraphPostInit` 包住 `sg.states.spawn.onexit` 再抢回来。
只写 `AddPrefabPostInit` 的话，出场动画播完就变回蓝色。灯光颜色也一并改成绯红。

### 重上色的第三个参数：按饱和度门控的明度曲线
第一版明度曲线把**白色细流光也压暗了**（fx_part_01 明度 0.686→0.638）。
加 `val_sat_gate=[0.12,0.35]`：明度曲线只作用在饱和度≥0.35 的像素（岩面），
低饱和高亮（辉光/流光）原样保留 → 流光回到 0.685，岩块该压的照样压。

### 三个新坑（Windows 上写 .ps1）
1. **含中文的 .ps1 必须存成 UTF-8 with BOM。** 系统自带的老版本按 GBK 读，无 BOM 时中文变乱码，
   而且「。」这类全角字符会**吞掉后面的引号**导致语法错误。用户原来那个脚本全英文所以没踩到。
2. **写文件时 newline='\r\n' + 内容本身已含 \r\n -> 写成 \r\r\n**（双重 CR）。
   写之前先 re.sub(r'\r+','',s) 归一化。
3. 脚本里用 Remove-Item -Recurse -Force 清目录，**当前环境会拦截递归删除**（trash 操作失败）。
   已改成 Clear-Dir 帮助函数：删不掉就降级为原地覆盖，两边都能跑。
